# AI 智能助手能力规格（Delta）

## ADDED Requirements

### Requirement: 悬浮入口与会话面板

系统 MUST 在用户登录后的主框架所有页面右下角提供固定的圆形 AI 助手入口按钮，图标使用 `public/logo.png`；登录/认证页面 MUST NOT 显示该入口。点击按钮 MUST 从右侧滑出聊天面板，再次点击关闭按钮 MUST 收起面板。

面板 MUST 支持：流式消息展示、文本输入（Enter 发送、Shift+Enter 换行）、生成过程中停止、清空当前会话、空状态下展示推荐问题。会话历史第一版仅保存在浏览器内存，刷新页面后清空是可接受行为。

#### Scenario: 登录后看到入口

- **WHEN** 用户登录后进入任意主框架页面
- **THEN** 右下角显示圆形 logo 助手按钮，点击后滑出聊天面板

#### Scenario: 登录页不显示入口

- **WHEN** 未登录用户访问登录页
- **THEN** 页面不出现 AI 助手按钮与面板

### Requirement: 流式对话协议

前端 MUST 通过 `POST /api/ai/chat` 与后端通信，后端 MUST 以 SSE（Server-Sent Events）返回，事件类型 MUST 为固定四种：`delta`（文本片段）、`toolcall`（需要确认的写操作）、`done`（本轮结束）、`error`（错误提示）。API Key MUST 仅保存在后端，任何接口响应 MUST NOT 包含 Key。

前端 MUST 使用 fetch + ReadableStream 读取流，并在发起新请求或清空会话时中断上一条未完成的流，避免多条流并发写同一会话。

#### Scenario: 普通问答流式输出

- **WHEN** 用户发送与系统操作无关的问题
- **THEN** 回复文字以打字机方式逐段出现在助手气泡中，结束后收到 done 事件

#### Scenario: AI 服务未配置

- **WHEN** 后端未配置 DeepSeek API Key
- **THEN** 前端收到 error 事件并在气泡中显示"AI 服务未配置"类提示，不抛出未捕获异常

### Requirement: 工具集与两档执行语义

第一版 MUST 提供且仅提供 6 个工具：查询用户、查询角色、查询部门、新增用户、新增角色、新增部门。

- **查询类工具**：当模型发起调用时，后端 MUST 在同一次请求内自动执行、把结果回喂模型继续作答，MUST NOT 要求用户确认。
- **新增类工具**：后端 MUST NOT 直接执行，MUST 通过 toolcall 事件把结构化参数下发给前端展示确认卡片；仅当用户显式确认后，经 `POST /api/ai/tool/execute` 才可落库。

工具参数 MUST 支持以中文名称指代部门与角色（如 deptName/parentName/roleNames），由后端解析为实际 id；无法解析时 MUST 返回可读错误让模型追问，MUST NOT 猜测或自动创建引用对象。

#### Scenario: 查询自动执行

- **WHEN** 用户问"系统里有哪些部门"
- **THEN** 后端自动执行部门查询并由模型基于真实数据流式回答，全程不出现确认卡片

#### Scenario: 新增必须确认

- **WHEN** 用户说"帮我新增一个角色叫财务专员"
- **THEN** 对话框出现包含角色名等参数的确认卡片，且在用户点击确认前数据库中 MUST NOT 出现该角色

#### Scenario: 确认后执行并反馈

- **WHEN** 用户在确认卡片上点击"确认执行"
- **THEN** 后端完成落库，卡片显示执行结果，随后模型用中文汇报创建结果（含新对象标识）

#### Scenario: 取消新增

- **WHEN** 用户在确认卡片上点击"取消"
- **THEN** 不发生任何数据变更，卡片标记为已取消，助手确认操作已取消

### Requirement: 服务端权限校验

每一个工具 MUST 映射到既有的功能权限码（查询→对应模块 `:List`，新增→对应模块 `:Add`）。后端在执行工具前 MUST 基于当前登录用户重新校验权限码；前端入口与确认按钮不作为安全边界。权限不足时 MUST 返回可由模型转述的中文错误，MUST NOT 执行该操作。

#### Scenario: 无新增权限的用户指令被拒绝

- **WHEN** 没有 System:Dept:Add 权限的登录用户要求 AI 新增部门
- **THEN** 确认后执行返回无权限错误，数据库无变更，助手回复解释缺少权限

### Requirement: 数据安全与结果裁剪

回喂给模型的查询结果 MUST 经过字段裁剪，MUST NOT 包含用户密码等敏感字段。写操作结果 MUST 经过现有 Admin Service 落库（复用既有校验与填充逻辑），MUST NOT 绕过业务层直接写表。单条用户消息超过 1000 字、会话历史超过 20 条时系统 MUST 进行截断。

#### Scenario: 查询用户结果不含敏感字段

- **WHEN** AI 调用查询用户工具并返回用户列表给模型
- **THEN** 结果中每个用户只包含 id、用户名、昵称、部门名、角色名、状态等必要字段，MUST NOT 包含密码、密码盐或 token 类字段

#### Scenario: 超长输入被截断

- **WHEN** 用户发送超过 1000 字的消息或会话历史超过 20 条
- **THEN** 系统截断后再发送给模型，接口正常返回，不出现因超长导致的服务端异常
