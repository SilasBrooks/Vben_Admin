# AI 智能助手能力规格（Delta）——菜单授权

## MODIFIED Requirements

### Requirement: 工具集与两档执行语义

系统 MUST 提供且仅提供 8 个工具：查询用户、查询角色、查询部门、查询菜单、新增用户、新增角色、新增部门、角色授权菜单。

- **查询类工具**：当模型发起调用时，后端 MUST 在同一次请求内自动执行、把结果回喂模型继续作答，MUST NOT 要求用户确认。
- **新增类工具**：后端 MUST NOT 直接执行，MUST 通过 toolcall 事件把结构化参数下发给前端展示确认卡片；仅当用户显式确认后，经 `POST /api/ai/tool/execute` 才可落库。

工具参数 MUST 支持以中文名称指代部门、角色与菜单（如 deptName/parentName/roleNames/menuNames），由后端解析为实际 id；无法解析时 MUST 返回可读错误让模型追问，MUST NOT 猜测或自动创建引用对象。

#### Scenario: 查询自动执行

- **WHEN** 用户问"系统里有哪些部门"
- **THEN** 后端自动执行部门查询并由模型基于真实数据流式回答，全程不出现确认卡片

#### Scenario: 新增必须确认

- **WHEN** 用户说"帮我新增一个角色叫财务专员"
- **THEN** 对话框出现包含角色名等参数的确认卡片，且在用户点击确认前数据库中 MUST NOT 出现该角色

#### Scenario: 确认后执行并反馈

- **WHEN** 用户在确认卡片上点击"确认执行"
- **THEN** 后端完成落库，卡片显示执行结果，随后模型用中文汇报创建结果（含新对象标识）

#### Scenario: 取消新增

- **WHEN** 用户在确认卡片上点击"取消"
- **THEN** 不发生任何数据变更，卡片标记为已取消，助手确认操作已取消

## ADDED Requirements

### Requirement: 菜单树查询工具

系统 MUST 提供 `query_menus` 查询类工具（权限码 `System:Menu:List`）：返回菜单全集的精简字段（id、菜单名、类型 M/C/F、上级 id、权限码、状态），供模型了解可分配范围。查询类工具按既有语义自动执行，MUST NOT 要求用户确认。

#### Scenario: 查询菜单树自动执行

- **WHEN** 用户问"系统里有哪些菜单"
- **THEN** 后端自动执行菜单查询并由模型基于真实菜单数据作答，全程不出现确认卡片

### Requirement: 角色菜单授权工具

系统 MUST 提供 `assign_role_menus` 写操作工具（权限码 `System:Role:Auth`）：参数为角色（中文名或 roleKey）与菜单中文名数组。后端 MUST 将名称解析为 id 并按以下规则补全：

- 目录名 → 该目录及全部后代（含按钮）
- 菜单名 → 该菜单 + 全部祖先目录 + 其直属按钮
- 按钮名 → 该按钮 + 全部祖先目录链

名称匹配到 0 个或多个时 MUST 返回可读错误让模型追问，MUST NOT 猜测。该工具属新增类写操作语义：MUST 经 toolcall 确认卡片、用户显式确认后执行；执行采用全量替换语义重建该角色菜单授权，执行结果 summary MUST 明示"全量替换"与生效菜单数量。

#### Scenario: 按目录名整模块授权

- **WHEN** 用户确认"给库存管理员分配库存管理"
- **THEN** 库存管理目录及其全部子菜单与按钮被授权给该角色，卡片显示菜单数量

#### Scenario: 授权自动补全父级

- **WHEN** 用户确认"给财务专员分配用户管理"
- **THEN** 系统管理目录（祖先链）、用户管理菜单及其按钮权限码一并写入角色菜单，该角色用户登录后可完整看到并使用该页面

#### Scenario: 名称歧义追问

- **WHEN** menuNames 中某名称匹配到 0 个或多个菜单
- **THEN** 不执行授权，返回可读错误由模型向用户追问，数据库无变更

#### Scenario: 全量替换语义告知

- **WHEN** 角色已有菜单授权且用户确认新的分配
- **THEN** 旧授权被整体替换，summary 明示"全量替换"与菜单数量
