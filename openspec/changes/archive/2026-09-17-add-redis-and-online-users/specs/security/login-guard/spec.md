## ADDED Requirements

### Requirement: Redis 集中存储

验证码、失败锁定、限流窗口的状态 MUST 存于 Redis（各状态 MUST 设置与业务时限一致的过期时间，不得永久驻留）；服务重启后进行中的锁定/限流窗口 MUST 保持有效；多实例部署 MUST 天然共享上述状态。Redis 连接不可用时，验证码签发、登录、被限流接口 MUST 快速失败并返回明确错误，MUST 不得静默降级为放行。

#### Scenario: 重启后锁定状态保持

- **WHEN** 某账号已触发登录锁定（429），此后后端服务重启
- **THEN** 重启后该账号仍处于锁定状态，登录继续返回 429 直至 Redis 中的窗口过期

#### Scenario: Redis 不可用快速失败

- **WHEN** Redis 宕机时用户请求验证码或登录
- **THEN** 接口返回明确错误（500/503 提示系统暂不可用），不会在无验证码校验的情况下放行登录

#### Scenario: 多实例共享限流计数

- **WHEN** 两台后端实例共同承接流量，同一 IP 在 1 分钟内跨实例累计向 /api/auth/login 发起超过 10 次请求
- **THEN** 超出部分返回 429（计数来源于共享的 Redis，而非各实例独立计数）

## REMOVED Requirements

### Requirement: 单实例内存语义边界

**Reason**: 三道防线（验证码/失败锁定/限流）状态已从应用内存迁移至 Redis，"内存态 + 单实例边界声明"的约束被"Redis 集中存储"取代。
**Migration**: 状态统一读写 Redis；代码与文档中原"单实例语义、多实例需迁移"的声明同步删除，改为声明 Redis 为必要依赖。
