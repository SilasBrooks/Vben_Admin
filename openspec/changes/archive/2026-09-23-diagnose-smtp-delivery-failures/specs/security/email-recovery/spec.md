## MODIFIED Requirements

### Requirement: 邮箱验证码与发送防护

邮件验证码 MUST 由安全随机数生成，为 6 位数字、5 分钟有效、最多 5 次校验尝试，成功 MUST 通过 Redis 原子校验销毁。不同用途 MUST 隔离，验证码 MUST NOT 在 API 响应或日志中明文回显。每账号同用途发信 MUST 间隔至少 60 秒，接口 MUST 限流并防重复提交；Redis 不可用 MUST 拒绝操作。前端绑定与找回密码的发码请求 MUST 使用独立的 60 秒超时，以容纳 SMTP 多阶段通信，不得沿用普通接口的 10 秒超时；只有接口成功返回挑战后才提示发送成功。

后端 MUST 为可识别的邮件连接失败、响应超时、认证失败、TLS 失败、邮箱不存在、收件地址拒绝和服务商拒绝发送提供本地化分类提示；未知原因 MUST 保留通用失败提示。服务商明确返回收件账号不存在时，中文提示 MUST 为「邮箱不存在，请检查邮箱地址后重新发送」，其他拒收不得错误归因为邮箱不存在。日志 MUST 仅记录固定错误分类、异常类型及可用的 SMTP 数字状态码，MUST NOT 记录原始异常文案、堆栈、邮箱地址、授权码、验证码或邮件正文。分类 MUST 支持逐邮件异常及嵌套异常，不得声称失败的邮件已发送成功。

#### Scenario: 重复请求或暴力猜测

- **WHEN** 请求命中发送冷却、接口限流或验证码尝试上限
- **THEN** 不继续发信或重置密码，验证码在尝试用尽后失效

#### Scenario: SMTP 未配置或发送失败

- **WHEN** 邮件功能未配置或 SMTP 发送失败
- **THEN** 返回明确可本地化的不可用或分类错误；找回页面提供联系管理员与返回登录入口，不声称发送成功，发送失败的验证码挑战被清除

#### Scenario: 发信耗时超过普通请求超时

- **WHEN** 发码接口在 10 秒后、60 秒内返回成功
- **THEN** 前端保持等待并接收挑战，允许用户输入邮件验证码继续绑定或重置，不提前提示请求超时

#### Scenario: 邮件服务商拒绝收件地址

- **WHEN** 底层异常表明 SMTP 服务商拒绝收件地址
- **THEN** 页面提示检查收件邮箱或联系管理员，日志仅保留分类、异常类型和数字状态码，不包含服务商原始文案或邮箱

#### Scenario: 嵌套连接异常

- **WHEN** 连接超时、TLS 或认证失败被包装在 cause、nextException 或逐邮件异常中
- **THEN** 返回对应的分类提示；异常链中的敏感信息不会出现在响应或日志中

#### Scenario: QQ 明确返回收件账号不存在

- **WHEN** QQ 在 DATA 阶段返回 550 及收件账号不存在的明确响应
- **THEN** 页面提示「邮箱不存在，请检查邮箱地址后重新发送」，不再显示笼统的邮件发送失败
