## MODIFIED Requirements

### Requirement: 列自定义统一持久化

所有已开放自定义列的列表 SHALL 使用稳定且独立的 key，在挂载时调用个人配置接口恢复列显隐、顺序、宽度和固定位置，调整后调用保存接口提交 JSON 数组。同一表格实例、同一登录用户的一次挂载期间 MUST 仅请求一次个人列配置，即使底层组件重复初始化列；保存或重置后下一次恢复 MUST 读取最新配置。系统 MUST 覆盖用户、角色、菜单、部门、字典类型、文件、模型配置、操作日志、登录日志、在线用户列表。系统 MUST 保留本地列标题、格式化函数、插槽与树形行为；序号和操作列也 MUST 有稳定标识。

#### Scenario: 刷新恢复布局
- **WHEN** 用户调整列布局并刷新或重新挂载列表
- **THEN** 使用同一 key 获取配置并按个人布局渲染

#### Scenario: 初始化重复加载列
- **WHEN** VXE 在表格挂载期间对同一列定义重复调用恢复钩子
- **THEN** 同一用户、同一表格实例只发起一次 GET `/user-config`，两次恢复使用同一结果

#### Scenario: 保存后重新恢复
- **WHEN** 用户调整或重置列配置后，当前表格实例再次调用恢复钩子
- **THEN** 等待待保存请求完成并读取最新配置，不使用调整前缓存的布局

#### Scenario: 重置列布局
- **WHEN** 用户点击自定义列面板的重置
- **THEN** 保存空数组且恢复默认，再次挂载仍为默认布局

#### Scenario: 列升级和损坏配置
- **WHEN** 配置引用已删除列、出现非法布局值或表格新增列
- **THEN** 忽略无效项，新增列保留默认设置，列业务渲染能力保持不变

#### Scenario: 请求失败与连续调整
- **WHEN** 读取失败、保存失败或用户连续调整后立即重新进入列表
- **THEN** 读取失败使用默认列；保存失败提示且后续仍能保存；同一用户同一列表保存按顺序执行，重新读取等待未完成保存

#### Scenario: 切换用户
- **WHEN** 旧用户仍有待发送保存任务但已切换登录账号
- **THEN** 旧任务不得以新用户身份发送，配置恢复不得跨账号复用
