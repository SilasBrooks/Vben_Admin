## Context

可自定义列表统一使用业务适配层 useVbenVxeGrid，VXE 4.18 提供 restoreStore/updateStore 钩子。后端尚无 user-config 接口。既有幂等注解按用户与动作锁定十秒，直接用于连续列调整会丢失后续设置。

## Goals / Non-Goals

- Goals：所有已开放列自定义的列表统一存取个人配置；跨设备恢复；表与用户隔离；保持格式化、插槽、国际化和树表行为。
- Non-Goals：不把仪表盘等未开放列自定义的表格改造成可自定义表格；不保存筛选条件、分页或行数据；不修改框架包。

## Decisions

- 每个列表显式指定稳定 gridOptions.id，作为配置 key。无 field 的序号、操作列补充稳定标识，不使用翻译标题或运行时 ID。
- 适配层利用 VXE 自定义存储钩子等待远程配置后完成列初始化，仅序列化布局信息为数组；配置为空、格式无效或读取失败时按默认列渲染，接口失败使用现有全局提示。
- 按同一用户与 key 串行保存，读取等待尚未完成的保存，避免快速调整、离开再进入时旧配置覆盖新配置。执行请求前检查当前用户，避免切换账号后的旧队列串号。
- sys_user_config 唯一约束为 (user_id, config_key)，配置内容为 TEXT 中的 JSON 数组；接口不接受目标用户 ID。空数组表示恢复默认。保存限制 key 格式、数组长度及内容大小。
- 保存采用先更新后插入、唯一键冲突后更新，兼容 PostgreSQL/MySQL，避免重复行。
- 幂等注解增加可选业务 key 表达式与 releaseAfterCompletion，使用随机锁令牌及 Redis 比较删除，仅新保存接口使用执行期间防重，旧接口保持时间窗防重。

## Risks

- 列结构更新：仅应用仍存在列的有效配置，新列保留默认，后端内容不用于覆盖标题、插槽或业务函数。
- 网络失败：默认列可使用；保存失败保留当前页面设置并提示，下一次调整允许重试。
- 存量库：提供幂等 SQL；dev/docker 初始化脚本也建表。
