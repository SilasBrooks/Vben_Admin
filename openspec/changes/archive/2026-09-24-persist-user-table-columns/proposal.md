## Why

现有十个可自定义列表的列设置没有保存到个人配置，刷新、重新登录或更换设备后无法恢复。用户需要反复调整列显隐、顺序及宽度，且无法在不同设备之间延续自己的列表布局。

## What Changes

- 新增 GET `/user-config?key=...` 与 POST `/user-config/save`，按当前用户与 key 保存 JSON 数组。
- 在业务 VXE 适配层统一接入原生自定义列存取钩子，覆盖用户、角色、菜单、部门、字典类型、文件、模型配置、操作日志、登录日志、在线用户十个列表。
- 保存列显隐、顺序、宽度、固定位置，挂载时恢复；重置保存空数组，失效列忽略，新列保持默认。
- 新建个人配置表及 PostgreSQL/MySQL 升级脚本，补充说明与验证。
- 扩展幂等注解的可选业务键与仅执行期间防重模式，使连续调整及不同列表保存互不阻塞，现有接口默认行为不变。

## Capabilities

### New Capabilities
- `system/user-config`：个人列表配置持久化。

### Modified Capabilities
- `security/idempotency`：支持按业务键隔离的执行期间防重。

## Impact

涉及业务前端适配层、十个列表标识、个人配置 API、后端 user 模块、幂等切面、数据库脚本及 README；不新增菜单权限，已登录用户仅能操作本人配置。
