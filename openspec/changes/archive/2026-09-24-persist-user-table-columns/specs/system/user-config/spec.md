## ADDED Requirements

### Requirement: 本人配置存取

系统 SHALL 提供 GET `/user-config`（query 参数 key）与 POST `/user-config/save`（JSON 对象 key、value，value 为 JSON 数组）。系统 MUST 从登录态获取用户身份，按当前用户和 key 读取或覆盖配置，不允许客户端指定其他用户。未保存返回空数组，保存空数组表示恢复默认。系统 MUST 校验 key、数组结构与大小，并通过唯一约束确保同一用户同一 key 只有一条配置。

#### Scenario: 保存与恢复
- **WHEN** 已登录用户保存某 key 的列配置后再次获取
- **THEN** 返回同一 JSON 数组，重新登录或更换设备仍可获取

#### Scenario: 用户和表格隔离
- **WHEN** 两个用户保存同一 key，或同一用户保存不同 key
- **THEN** 各自配置独立，读取只返回本人对应 key 的配置

#### Scenario: 未认证或非法请求
- **WHEN** 未登录访问或提交非法 key、非数组、超大配置
- **THEN** 未登录返回 401，非法输入返回 400 且不保存

### Requirement: 列自定义统一持久化

所有已开放自定义列的列表 SHALL 使用稳定且独立的 key，在挂载时调用个人配置接口恢复列显隐、顺序、宽度和固定位置，调整后调用保存接口提交 JSON 数组。系统 MUST 覆盖用户、角色、菜单、部门、字典类型、文件、模型配置、操作日志、登录日志、在线用户列表。系统 MUST 保留本地列标题、格式化函数、插槽与树形行为；序号和操作列也 MUST 有稳定标识。

#### Scenario: 刷新恢复布局
- **WHEN** 用户调整列布局并刷新或重新挂载列表
- **THEN** 使用同一 key 获取配置并按个人布局渲染

#### Scenario: 重置列布局
- **WHEN** 用户点击自定义列面板的重置
- **THEN** 保存空数组且恢复默认，再次挂载仍为默认布局

#### Scenario: 列升级和损坏配置
- **WHEN** 配置引用已删除列、出现非法布局值或表格新增列
- **THEN** 忽略无效项，新增列保留默认设置，列业务渲染能力保持不变

#### Scenario: 请求失败与连续调整
- **WHEN** 读取失败、保存失败或用户连续调整后立即重新进入列表
- **THEN** 读取失败使用默认列；保存失败提示且后续仍能保存；同一用户同一列表保存按顺序执行，重新读取等待未完成保存

#### Scenario: 切换用户
- **WHEN** 旧用户仍有待发送保存任务但已切换登录账号
- **THEN** 旧任务不得以新用户身份发送，配置恢复不得跨账号复用
