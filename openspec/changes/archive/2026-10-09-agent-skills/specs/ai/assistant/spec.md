## ADDED Requirements

### Requirement: 技能清单注入与按需加载

系统 MUST 实现技能的渐进式披露两级加载：

1. **常驻清单**：每轮对话开始时，系统提示词 MUST 动态拼接当前全部启用技能的清单（name + 中文能力名 + 场景描述），并附调用指引（需要某能力的方法论时先调用 activate_skill 加载完整正文）。无启用技能时 MUST NOT 注入任何技能段落，对话行为与未引入技能机制前完全一致。
2. **按需加载**：系统 MUST 提供 `activate_skill` 查询类工具（无需权限码，登录即可调用）：参数为技能 name，后端校验存在且启用后返回该技能完整正文（Markdown）回喂模型。name 不存在或已停用 MUST 返回可读错误说明，MUST NOT 返回其他技能内容。

单轮对话中技能清单注入 MUST 有总长上限（超限截断并保证清单仍完整可读）；activate_skill 查询失败 MUST 以状态说明回喂模型，MUST NOT 中断本轮对话。技能新增、编辑、停用后 MUST 无需重启，下一次对话即生效。

#### Scenario: 清单常驻引导加载
- **WHEN** 存在启用技能「公告写作助手」且用户要求起草公告
- **THEN** 模型从系统提示词清单得知该能力，调用 activate_skill 加载正文后按技能指令起草，全程不出现确认卡片

#### Scenario: 无启用技能零影响
- **WHEN** 全部技能处于停用状态
- **THEN** 系统提示词不含技能段落，AI 对话与引入技能机制前行为一致

#### Scenario: 技能不存在返回可读错误
- **WHEN** 模型调用 activate_skill 传入不存在的 name
- **THEN** 工具返回「技能不存在或已停用」状态说明，模型如实告知用户，本轮对话继续

#### Scenario: 修改即时生效
- **WHEN** 管理员编辑技能正文后用户立刻提问相关能力
- **THEN** 模型加载到的是编辑后的正文，无需重启服务
