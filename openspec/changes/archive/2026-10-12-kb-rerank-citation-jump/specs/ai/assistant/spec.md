# ai/assistant Delta

## MODIFIED Requirements

### Requirement: 知识库引用溯源卡片

当本轮对话执行 `search_knowledge` 工具且检索命中时，后端 MUST 通过 SSE 事件 `citations` 下发结构化出处列表，每条出处 SHALL 包含文档名（docName）、文档 id（docId）、块序号（seq）、得分（score，有精排时为精排得分）与内容摘要（content，与回喂模型的片段一致并同样裁剪）。一次对话中出现多次命中 SHALL 逐次下发或合并下发，前端 MUST 按文档 id + 块序号去重后在对应助手气泡下方渲染溯源卡片。

溯源卡片 MUST 展示文档名、块序号与得分，默认收起内容摘要（可展开查看完整摘要文本）；卡片 SHALL 提供「查看原文」入口（出处含 docId 时），点击后 SHALL 打开文档原文预览弹窗：调用文档预览接口加载按块分隔的文档正文，SHALL 自动滚动定位到引用块并高亮标记；文档已删除或加载失败时 MUST 展示可读错误提示。出处不含 docId 时（存量会话恢复场景）MUST 隐藏该入口。卡片数量上限与回喂片段数一致（Top-K）。卡片渲染 MUST 与 Markdown 正文互不干扰，且 MUST NOT 引入 HTML 注入风险（摘要按纯文本展示）。

文档原文预览接口 SHALL 仅要求登录态（与 search_knowledge「知识库面向全体登录用户」语义一致，不加 Kb:Doc:List 权限码），返回文档名与按块序号升序的正文块列表，MUST 有限流防护。

前端卡片数据仅存在于本轮会话内存（与消息气泡同生命周期），刷新页面后随会话恢复流程一并丢失属于可接受行为。

#### Scenario: 命中后展示溯源卡片

- **WHEN** 用户问「系统的接入流程是什么」，模型调用 search_knowledge 命中 2 个片段
- **THEN** 回答气泡下方出现 2 张溯源卡片，展示文档名、块序号与得分，点击可展开内容摘要

#### Scenario: 重复命中去重

- **WHEN** 同一轮对话模型先后两次调用 search_knowledge，两次结果含相同文档与块序号的片段
- **THEN** 气泡下的溯源卡片按文档 id + 块序号去重，不出现重复卡片

#### Scenario: 未命中不出卡片

- **WHEN** search_knowledge 返回未命中状态说明
- **THEN** 不下发 citations 事件，气泡下无溯源卡片

#### Scenario: 查看原文定位引用块

- **WHEN** 用户点击某溯源卡片的「查看原文」
- **THEN** 弹窗展示该文档按块分隔的正文，自动滚动到引用块并高亮

#### Scenario: 文档已删除后查看原文

- **WHEN** 溯源卡片对应文档已被删除，用户点击「查看原文」
- **THEN** 弹窗展示可读错误提示（文档不存在或已删除），不阻塞对话面板

#### Scenario: 无 docId 隐藏入口

- **WHEN** 刷新页面后恢复的会话中存在不含 docId 的存量溯源卡片
- **THEN** 卡片不渲染「查看原文」入口，其余功能正常
