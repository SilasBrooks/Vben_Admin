# ai/assistant Specification

## Purpose

在管理后台提供右下角自然语言智能助手：流式对话查询用户/角色/部门，新增类写操作经用户显式确认并经服务端权限校验后执行，降低系统操作门槛。

## Requirements

### Requirement: 悬浮入口与会话面板

系统 MUST 在用户登录后的主框架所有页面右下角提供固定的圆形 AI 助手入口按钮，图标使用 `public/logo.png`；登录/认证页面 MUST NOT 显示该入口。点击按钮 MUST 从右侧滑出聊天面板，再次点击关闭按钮 MUST 收起面板。

面板 MUST 支持：流式消息展示、文本输入（Enter 发送、Shift+Enter 换行）、生成过程中停止、清空当前会话、空状态下展示推荐问题。会话历史第一版仅保存在浏览器内存，刷新页面后清空是可接受行为。

#### Scenario: 登录后看到入口

- **WHEN** 用户登录后进入任意主框架页面
- **THEN** 右下角显示圆形 logo 助手按钮，点击后滑出聊天面板

#### Scenario: 登录页不显示入口

- **WHEN** 未登录用户访问登录页
- **THEN** 页面不出现 AI 助手按钮与面板

### Requirement: 流式对话协议

前端 MUST 通过 `POST /api/ai/chat` 与后端通信，后端 MUST 以 SSE（Server-Sent Events）返回，事件类型 MUST 为固定四种：`delta`（文本片段）、`toolcall`（需要确认的写操作）、`done`（本轮结束）、`error`（错误提示）。API Key MUST 仅保存在后端，任何接口响应 MUST NOT 包含 Key。

前端 MUST 使用 fetch + ReadableStream 读取流，并在发起新请求或清空会话时中断上一条未完成的流，避免多条流并发写同一会话。

#### Scenario: 普通问答流式输出

- **WHEN** 用户发送与系统操作无关的问题
- **THEN** 回复文字以打字机方式逐段出现在助手气泡中，结束后收到 done 事件

#### Scenario: AI 服务未配置

- **WHEN** 后端未配置 DeepSeek API Key
- **THEN** 前端收到 error 事件并在气泡中显示"AI 服务未配置"类提示，不抛出未捕获异常

### Requirement: 工具集与两档执行语义

系统 MUST 提供且仅提供 8 个工具：查询用户、查询角色、查询部门、查询菜单、新增用户、新增角色、新增部门、角色授权菜单。

- **查询类工具**：当模型发起调用时，后端 MUST 在同一次请求内自动执行、把结果回喂模型继续作答，MUST NOT 要求用户确认。
- **新增类工具**：后端 MUST NOT 直接执行，MUST 通过 toolcall 事件把结构化参数下发给前端展示确认卡片；仅当用户显式确认后，经 `POST /api/ai/tool/execute` 才可落库。

工具参数 MUST 支持以中文名称指代部门、角色与菜单（如 deptName/parentName/roleNames/menuNames），由后端解析为实际 id；无法解析时 MUST 返回可读错误让模型追问，MUST NOT 猜测或自动创建引用对象。

#### Scenario: 查询自动执行

- **WHEN** 用户问"系统里有哪些部门"
- **THEN** 后端自动执行部门查询并由模型基于真实数据流式回答，全程不出现确认卡片

#### Scenario: 新增必须确认

- **WHEN** 用户说"帮我新增一个角色叫财务专员"
- **THEN** 对话框出现包含角色名等参数的确认卡片，且在用户点击确认前数据库中 MUST NOT 出现该角色

#### Scenario: 确认后执行并反馈

- **WHEN** 用户在确认卡片上点击"确认执行"
- **THEN** 后端完成落库，卡片显示执行结果，随后模型用中文汇报创建结果（含新对象标识）

#### Scenario: 取消新增

- **WHEN** 用户在确认卡片上点击"取消"
- **THEN** 不发生任何数据变更，卡片标记为已取消，助手确认操作已取消

### Requirement: 菜单树查询工具

系统 MUST 提供 `query_menus` 查询类工具（权限码 `System:Menu:List`）：返回菜单全集的精简字段（id、菜单名、类型 M/C/F、上级 id、权限码、状态），供模型了解可分配范围。查询类工具按既有语义自动执行，MUST NOT 要求用户确认。

#### Scenario: 查询菜单树自动执行

- **WHEN** 用户问"系统里有哪些菜单"
- **THEN** 后端自动执行菜单查询并由模型基于真实菜单数据作答，全程不出现确认卡片

### Requirement: 角色菜单授权工具

系统 MUST 提供 `assign_role_menus` 写操作工具（权限码 `System:Role:Auth`）：参数为角色（中文名或 roleKey）与菜单中文名数组。后端 MUST 将名称解析为 id 并按以下规则补全：

- 目录名 → 该目录及全部后代（含按钮）
- 菜单名 → 该菜单 + 全部祖先目录 + 其直属按钮
- 按钮名 → 该按钮 + 全部祖先目录链

名称匹配到 0 个或多个时 MUST 返回可读错误让模型追问，MUST NOT 猜测。该工具属新增类写操作语义：MUST 经 toolcall 确认卡片、用户显式确认后执行；执行采用全量替换语义重建该角色菜单授权，执行结果 summary MUST 明示"全量替换"与生效菜单数量。

#### Scenario: 按目录名整模块授权

- **WHEN** 用户确认"给库存管理员分配库存管理"
- **THEN** 库存管理目录及其全部子菜单与按钮被授权给该角色，卡片显示菜单数量

#### Scenario: 授权自动补全父级

- **WHEN** 用户确认"给财务专员分配用户管理"
- **THEN** 系统管理目录（祖先链）、用户管理菜单及其按钮权限码一并写入角色菜单，该角色用户登录后可完整看到并使用该页面

#### Scenario: 名称歧义追问

- **WHEN** menuNames 中某名称匹配到 0 个或多个菜单
- **THEN** 不执行授权，返回可读错误由模型向用户追问，数据库无变更

#### Scenario: 全量替换语义告知

- **WHEN** 角色已有菜单授权且用户确认新的分配
- **THEN** 旧授权被整体替换，summary 明示"全量替换"与菜单数量

### Requirement: 服务端权限校验

每一个工具 MUST 映射到既有的功能权限码（查询→对应模块 `:List`，新增→对应模块 `:Add`/`:Auth`）。后端在执行工具前 MUST 基于当前登录用户重新校验权限码；前端入口与确认按钮不作为安全边界。权限不足时 MUST 返回可由模型转述的中文错误，MUST NOT 执行该操作。

编排循环中，写操作工具的 toolcall 确认事件 MUST NOT 下发给无对应用户权限的请求：模型调用无权限的写操作工具时，系统 MUST 将权限不足结果回喂模型继续本轮对话，由模型直接告知用户"你的权限不足"；确认卡片仅在用户具备对应权限时出现。确认执行接口 `POST /api/ai/tool/execute` MUST 保留独立权限校验作为纵深防御。

#### Scenario: 无新增权限的用户指令被拒绝

- **WHEN** 没有 System:Dept:Add 权限的登录用户要求 AI 新增部门
- **THEN** 确认后执行返回无权限错误，数据库无变更，助手回复解释缺少权限

#### Scenario: 无权限用户请求写操作直接获知权限不足

- **WHEN** 没有 System:User:Add 权限的登录用户要求 AI 创建用户
- **THEN** 助手直接回复"你的权限不足"并说明缺少的权限，全程不出现确认卡片，数据库无变更

#### Scenario: 无权限用户请求查询获知权限不足

- **WHEN** 没有 System:User:List 权限的登录用户询问"系统里有哪些用户"
- **THEN** 查询工具自动执行失败并回喂模型，助手回复"你的权限不足"，不出现编造数据

### Requirement: 数据安全与结果裁剪

回喂给模型的查询结果 MUST 经过字段裁剪，MUST NOT 包含用户密码等敏感字段。写操作结果 MUST 经过现有 Admin Service 落库（复用既有校验与填充逻辑），MUST NOT 绕过业务层直接写表。单条用户消息超过 1000 字、会话历史超过 20 条时系统 MUST 进行截断。

#### Scenario: 查询用户结果不含敏感字段

- **WHEN** AI 调用查询用户工具并返回用户列表给模型
- **THEN** 结果中每个用户只包含 id、用户名、昵称、部门名、角色名、状态等必要字段，MUST NOT 包含密码、密码盐或 token 类字段

#### Scenario: 超长输入被截断

- **WHEN** 用户发送超过 1000 字的消息或会话历史超过 20 条
- **THEN** 系统截断后再发送给模型，接口正常返回，不出现因超长导致的服务端异常
