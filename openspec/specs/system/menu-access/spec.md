# system/menu-access Specification

## Purpose
明确后台页面的登录校验与菜单初始化时机，保证刷新、新窗口和登录回跳后的菜单可用，并支持多个菜单分组独立展开。

## Requirements

### Requirement: 后台路由进入前初始化菜单

系统 MUST 仅对显式声明公开访问的认证路由跳过登录检查。已登录用户在系统更新后刷新页面或新开窗口首次访问后台路由时，MUST 在导航完成前加载用户信息、权限码、菜单并注册动态路由，包括个人中心、消息中心及未找到页面。系统 MUST 保留目标地址的路径、查询参数和锚点，并在注册动态路由后重新匹配地址。菜单初始化成功后 MUST 在当前页面上下文中复用结果，失败时 MUST NOT 标记为完成。

#### Scenario: 刷新或新窗口直达基础后台页面

- **WHEN** 已登录用户在新的页面上下文直接进入个人中心或消息中心
- **THEN** 菜单初始化完成后才进入目标页面，侧边栏正常显示

#### Scenario: 首次直达动态路由

- **WHEN** 已登录用户直接打开含查询参数或锚点的动态业务地址
- **THEN** 加载菜单并注册动态路由后进入对应页面，保留查询参数及锚点

#### Scenario: 未登录访问后台页面

- **WHEN** 未登录用户打开个人中心、消息中心或动态业务地址
- **THEN** 跳转登录页并保留回跳地址，不加载受保护的菜单

#### Scenario: 公开认证页面

- **WHEN** 未登录用户访问登录或忘记密码页面
- **THEN** 正常显示页面，不请求菜单

#### Scenario: 后续导航与初始化失败

- **WHEN** 当前页面上下文已成功初始化菜单后切换页面
- **THEN** 复用菜单结果，不重复初始化；若之前菜单请求失败，则下次导航仍可重新初始化

### Requirement: 菜单分组独立展开

系统 MUST 默认关闭侧边菜单手风琴模式。用户展开新菜单分组或选择其中的菜单项时，MUST 保留其他分组的展开状态；仅在用户主动收起对应分组时折叠该分组。系统更新或刷新后，应用显式配置 MUST 优先于历史手风琴模式缓存。

#### Scenario: 连续展开不同分组

- **WHEN** 用户已展开一个菜单分组，再展开另一个分组或选择其中的菜单项
- **THEN** 两个分组同时保持展开，用户可以独立收起任一分组

#### Scenario: 旧缓存升级

- **WHEN** 用户历史偏好缓存启用了手风琴模式，更新应用后重新打开页面
- **THEN** 应用覆盖配置生效，菜单分组可同时展开

### Requirement: 菜单变更后应用内同步

菜单管理新增、修改或删除成功后，系统 MUST 在应用内刷新管理列表，重新读取 `/user-config?key=menu`、当前用户信息与权限码，并更新侧边栏、动态路由和权限按钮，MUST NOT 通过 location.reload 或等价方式重新加载整个文档。系统 MUST 清除已删除或失去访问权限的动态路由。未改变路由页面组件时 MUST 保留当前页面状态、有效标签页、查询参数、锚点和滚动位置；标签和面包屑 MUST 使用最新菜单元数据。当前路由失效时 MUST 跳转仍可访问的页面，并清理无效标签和缓存。

#### Scenario: 修改标题图标排序或可见性
- **WHEN** 用户修改菜单标题、图标、排序或侧边栏可见性并保存成功
- **THEN** 管理列表、侧边栏和相关标签元数据更新，文档不重新加载，仍有权访问的当前页面和输入状态保留

#### Scenario: 新增删除或修改路由
- **WHEN** 用户新增、删除、停用菜单或修改路径、组件
- **THEN** 路由表与最新权限菜单一致，新菜单可以进入，旧路径和已移除菜单不再可访问，失效标签和缓存被清理

#### Scenario: 当前页面失效
- **WHEN** 菜单变更导致当前页面被删除、改路径或失去权限
- **THEN** 尝试跳转仍可访问的用户首页或默认首页，若均不可用则进入个人中心，不出现空白页或跳转循环

#### Scenario: 按钮权限变化
- **WHEN** 菜单变更导致当前用户权限码增加或减少
- **THEN** 已挂载页面中的 v-access 按钮立即显示或隐藏，无需重挂载整个页面

#### Scenario: 保存成功但同步失败
- **WHEN** 写入已成功，但后续菜单、用户信息或权限码请求失败
- **THEN** 保留原可用路由与页面，提示同步失败并提供重试入口；重试不重复提交保存或删除操作

#### Scenario: 连续修改与账号切换
- **WHEN** 前一次菜单同步尚未完成时再次修改，或期间退出登录并切换账号
- **THEN** 同账号同步按顺序执行，后一次使用最新数据；旧账号请求不得写入当前账号的菜单、权限或路由

#### Scenario: 再次打开菜单选择弹窗
- **WHEN** 菜单变更后重新打开菜单编辑或角色菜单授权弹窗
- **THEN** 使用最新菜单树，不显示已删除项并可选择新增项
