# system/menu-access Specification

## Purpose
明确后台页面的登录校验与菜单初始化时机，保证刷新、新窗口和登录回跳后的菜单可用，并支持多个菜单分组独立展开。

## Requirements

### Requirement: 后台路由进入前初始化菜单

系统 MUST 仅对显式声明公开访问的认证路由跳过登录检查。已登录用户在系统更新后刷新页面或新开窗口首次访问后台路由时，MUST 在导航完成前加载用户信息、权限码、菜单并注册动态路由，包括个人中心、消息中心及未找到页面。系统 MUST 保留目标地址的路径、查询参数和锚点，并在注册动态路由后重新匹配地址。菜单初始化成功后 MUST 在当前页面上下文中复用结果，失败时 MUST NOT 标记为完成。

#### Scenario: 刷新或新窗口直达基础后台页面

- **WHEN** 已登录用户在新的页面上下文直接进入个人中心或消息中心
- **THEN** 菜单初始化完成后才进入目标页面，侧边栏正常显示

#### Scenario: 首次直达动态路由

- **WHEN** 已登录用户直接打开含查询参数或锚点的动态业务地址
- **THEN** 加载菜单并注册动态路由后进入对应页面，保留查询参数及锚点

#### Scenario: 未登录访问后台页面

- **WHEN** 未登录用户打开个人中心、消息中心或动态业务地址
- **THEN** 跳转登录页并保留回跳地址，不加载受保护的菜单

#### Scenario: 公开认证页面

- **WHEN** 未登录用户访问登录或忘记密码页面
- **THEN** 正常显示页面，不请求菜单

#### Scenario: 后续导航与初始化失败

- **WHEN** 当前页面上下文已成功初始化菜单后切换页面
- **THEN** 复用菜单结果，不重复初始化；若之前菜单请求失败，则下次导航仍可重新初始化

### Requirement: 菜单分组独立展开

系统 MUST 默认关闭侧边菜单手风琴模式。用户展开新菜单分组或选择其中的菜单项时，MUST 保留其他分组的展开状态；仅在用户主动收起对应分组时折叠该分组。系统更新或刷新后，应用显式配置 MUST 优先于历史手风琴模式缓存。

#### Scenario: 连续展开不同分组

- **WHEN** 用户已展开一个菜单分组，再展开另一个分组或选择其中的菜单项
- **THEN** 两个分组同时保持展开，用户可以独立收起任一分组

#### Scenario: 旧缓存升级

- **WHEN** 用户历史偏好缓存启用了手风琴模式，更新应用后重新打开页面
- **THEN** 应用覆盖配置生效，菜单分组可同时展开
